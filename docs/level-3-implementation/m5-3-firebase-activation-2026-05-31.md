# FreshLoop M5.3 — Activate Firebase at runtime · Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans. Checkbox steps.

**Goal:** Turn on the M5.2 Firebase code at runtime (guarded `Firebase.initializeApp`, an auth gate that shows sign-in when signed out, and Firestore-backed history/favourites scoped to the signed-in user), without breaking the app when Firebase is absent (tests, web screenshots, fresh clones). Project `freshloop-86034` is already configured: `lib/firebase_options.dart` + `android/app/google-services.json` exist (generated by `flutterfire configure`), the google-services Gradle plugin is applied, and `firebase.json` is updated.

**THE CRITICAL INVARIANT:** When Firebase is NOT initialized, nothing may touch `FirebaseAuth.instance` / `FirebaseFirestore.instance` (they throw if `Firebase.initializeApp` hasn't run). The existing 111 tests plus `test/app/smoke_test.dart` must stay green; they pump `FreshLoopApp` without initializing Firebase. So all Firebase access is gated behind a `firebaseReady` flag (default `false`), and the whole auth/cloud path is bypassed when it's false (it falls back to M5.1 local storage, i.e. today's behaviour).

## Architecture

1. **`firebaseReady` flag** (in `dependencies.dart`, default `false`). Set `true` only by `main()` after a successful `Firebase.initializeApp`.
2. **`main.dart`** — guarded init:
```dart
import 'package:firebase_core/firebase_core.dart';
import 'firebase_options.dart';
// ...
Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  appPrefs = await SharedPreferences.getInstance();
  try {
    await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);
    firebaseReady = true;
  } catch (_) {
    firebaseReady = false; // run on local storage if config/init unavailable
  }
  runApp(const FreshLoopApp());
}
```
3. **`dependencies.dart`** — repo factories choose cloud vs local by uid:
```dart
bool firebaseReady = false;
AuthRepository buildAuthRepository() => FirebaseAuthRepository(FirebaseAuth.instance);
RunHistoryRepository buildHistoryRepository() {
  final uid = firebaseReady ? FirebaseAuth.instance.currentUser?.uid : null;
  return uid != null
      ? FirestoreRunHistoryRepository(FirebaseFirestore.instance, uid)
      : SharedPrefsRunHistoryRepository(appPrefs);
}
FavoritesRepository buildFavoritesRepository() {
  final uid = firebaseReady ? FirebaseAuth.instance.currentUser?.uid : null;
  return uid != null
      ? FirestoreFavoritesRepository(FirebaseFirestore.instance, uid)
      : SharedPrefsFavoritesRepository(appPrefs);
}
```
   (`firebaseReady ? ... : null` short-circuits so `FirebaseAuth.instance` is never read when not ready.)
4. **Router** must NOT touch `FirebaseAuth.instance` at import time (top-level `appRouter` is built when the library loads, before `main` runs, which would crash tests). So:
   - Convert `appRouter` from a top-level `final` into a **function** `GoRouter buildRouter()` (or build it inside `FreshLoopApp`), and add a `'/sign-in'` route.
   - Add a `redirect` that gates **only when `firebaseReady`**: signed-out → `/sign-in`; signed-in & at `/sign-in` → `/`; otherwise null. When `!firebaseReady`, redirect returns `null` (no gating, so today's behaviour).
   - `refreshListenable`: a `GoRouterRefreshStream` wrapping `FirebaseAuth.instance.authStateChanges()`, only constructed when `firebaseReady` (else pass `null`).
5. **`app.dart`** — two modes:
   - **Local mode** (`!firebaseReady` AND no injected `authRepository`): exactly today's tree (`RouteGenCubit` + `FavoritesCubit(local)` + `MaterialApp.router`). No `AuthCubit`, no Firebase touched. *(keeps smoke test green)*
   - **Firebase mode** (`firebaseReady` OR an `authRepository` is injected for tests): provide `RouteGenCubit` + `AuthCubit`; wrap the router subtree in `BlocBuilder<AuthCubit, AuthState>` and key the `FavoritesCubit` provider on the current uid (`KeyedSubtree(key: ValueKey(uid ?? '_out_'))`) so the favourites cubit is rebuilt against the right repo when the user signs in/out.
   - Add an injectable `AuthRepository? authRepository` to `FreshLoopApp` (mirrors `generator`/`favoritesRepository`) so an AuthGate widget test can drive it with a fake.
6. **Sign-out UI:** add a sign-out icon to the home screen's top-right nav row (next to history/favourites), shown only in Firebase mode (`context.read<AuthCubit>()` available); it calls `signOut()`. The redirect then returns the user to `/sign-in`.

## Self-Review (author)

**Spec coverage:** runtime activation = guarded init (Task 1) + auth gate (Task 2) + sign-out (Task 3); cloud repos scoped to uid via the factories (Task 1) and uid-keyed favourites provider (Task 2). Test-green invariant enforced by the `firebaseReady` short-circuit everywhere.

**Risk register:** (1) Top-level `FirebaseAuth.instance` access crashing tests → mitigated by converting `appRouter` to a function and only touching Firebase when `firebaseReady`. (2) App-wide `FavoritesCubit` not reflecting the signed-in uid → uid-keyed provider rebuild. (3) Smoke test → stays in local mode (`!firebaseReady`). (4) Android build needs `google-services.json` (gitignored) → documented; web + tests unaffected. (5) `flutter test` must not require real Firebase → all Firebase classes only constructed at runtime when ready / via injected fakes in tests.

**Type consistency:** factories return the M5.1 `RunHistoryRepository`/`FavoritesRepository` interfaces (Firestore or SharedPrefs impl); `AuthCubit` consumes `AuthRepository` (Firebase impl or injected fake); router adds `/sign-in` → `SignInScreen` (M5.2). No change to the scoring/route-gen/tracking code.
